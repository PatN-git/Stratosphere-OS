## Design notes
- **Findings record (1):** a separate top-level `audit:` block line keyed by slice id (`spec_r1, spec_final, std_hard, std_judg, phase1, std_tier`, where `std_tier` is the BT-204 tier name dispatched for the Standards auditor, absent if unset; `input` = `lean`|`full`, how the Spec auditor was fed, so BT-203's change is visible in the data; `rounds` stays on the slice row). The slice row stays byte-identical because `SLICE_RE` is anchored on `audit_rounds: (\d+)}` and an in-row field would revert old readers' rows to `PENDING`. Schema in `references/pr-body-and-ship.md`, not the 4a body. Old and new PR bodies must round-trip in both directions (CleanTechHub vendors its own `pr_body.py`). Tokens are measured offline, not logged. 3z returns and passes the counts through, or AFK slices (CleanTechHub's majority) record nothing.
- **Cost levers (2, 4):** BT-185's lean inline path cost 65k tokens vs a 493k median; BT-187's three full rounds cost 1.94M. Round 2+ carries PASS rows forward and re-checks only failed ACs plus rows the fix touched (no extra full pass: it would cost more than today's two full audits). Same gaps found at fewer tokens is the acceptance test, validated on 3 replayed slices. `auditor_model` is a named tier (for example `small`) each host maps to its own subagent model setting in a shipped reference; unsupported hosts fall back to the default silently.
- **Rule bindings (R), decided 2026-10-22 after an independent Opus 5.5 (high effort) review of the "CleanTechHub-local checker" idea.** Verdict: the checks stay project-local (stack-specific; the fix ladder's rung 1 already says lint, test), but the governance around them is a framework need: the 400-line rule ships in the framework template (`src/memory-templates/ARCHITECTURE.md:69`), StratOS breaks it itself (`scaffold.py` 1636 lines), and agreed exceptions were never recorded, so every audit re-flagged them. Spike A: 39% of 70 sampled hard rows were mechanical, 30% baseline smells labelled Hard, 27% real defects or documented-rule judgment. Parts:
  - **Binding marker:** a `[LAW]` entry in `.memory/` may end with `Check: <repo path>` (for example `Check: tests/standards/file-length.test.js`, with a tolerance noted beside it). The framework never runs the check; the project's own suite does, in 3d Phase 3 step 6 and CI. `validate_memory.py` (already run by 0b) errors when the path is not in `git ls-files`, so a stale binding cannot silently disable auditing. Only a human writes it (a `[LAW]` edit).
  - **Exceptions reuse `## Floor exceptions`:** widen `EXC_RE` (`floor_guard.py:53`) so the rule field also accepts memory rule IDs (`A-003 src/pages/JobView.jsx — legacy, split later`). Rows are read from the default-branch tip, a row added on a branch already exits 1, 3z already refuses a new row as a fix, and removing a row is silent tightening. No `baseline.json`, no `exceptions.json`. A glob row such as `A-003 **/*.test.* — tests exempt` carries test-file exemptions. The rule text stays at 400 lines; a project's check may tolerate 10% (warn at 401 to 440, fail above) in the check, not in the rule.
  - **Auditor contract (no always-loaded text):** in `references/code-smell-baseline.md` (already loaded by the Standards auditor) plus one clause in 4a Phase 2 item 2 and 3z Step 2B: skip any rule carrying `Check:` (the rule, not the file: defects there are still reported); drop findings matching a rule ID and glob in `## Floor exceptions`; the lead passes those rows to the auditor. Severity label fix: `Hard breach` only for a cited rule ID or an objective defect; every baseline smell is `Judgment`.
  - **Ladder and template:** one sentence in `environment-fix-ladder.md` rung 1 (a check enforcing an existing `[LAW]` is bound by `Check:` and the auditor stops judging it; promotion stays with the ladder's Escalation rule, 0b/0d and a human); a commented example `## Floor exceptions` row in the template ARCHITECTURE.md. The constitution (`AGENTS.md`, 9192 of 9200 characters) is untouched.
  - **Evidence gates:** E1 (floor_guard unit tests): a rule-ID row added on a branch exits 1, the same row on the default tip suppresses the finding, removal is silent, existing floor tests stay green. E2 (auditor wording, replay): re-run on 4 slices with mislabelled rows (BT-168, 172, 189, 193), the 2 real-defect slices (BT-187, BT-222) and 2 with size or index rows, using seeded markers and rows. Pass: no baseline smell labelled Hard, both defects still Hard, no finding on a bound rule or excepted path. Fail: any of those in 2 of 8 runs, or a real defect lost; revise the wording, do not ship (handoff caution: no auditor prompt change without an experiment).
  - **Rejected:** a framework `standards_guard.py` runner with a config format (re-implements the test runner, adds a ship-path step, repeats the deferred spec_lint pattern); a framework library of detectors (stack-specific, one consumer); automatic promotion after N auditor flags (the `audit:` line records counts, not rule IDs, so there is no data; deferred); auditor-only change (leaves exceptions unprotected and mechanical rows costing LLM passes).
- **Local checks (L), a CleanTechHub slice:** vitest tests in `tests/standards/` run by `npm test` (so 3d's full-suite run and CI catch violations before 4a), a minimal ESLint (`no-unused-vars`, `no-undef`, array-index keys, `--max-warnings 0`), `Check:` markers on A-003, A-008 and DR-002/005/023, and today's offenders as human-merged exception rows. A-008's "same commit" condition becomes a final-state manifest check; commit-level enforcement is dropped on purpose. E3: each check goes red at the pre-fix SHA of its motivating instance (BT-185 for A-003, BT-170 for A-008), is green on current main with the exception rows, has no other false positive, and adds at most 2 seconds to `npm test` (median of 3 runs). Deferred: a `std_rules` field on the `audit:` line, a `check-edited` guard on bound test files.
- **Standards fix round (3), decided 2026-10-22 (supersedes "hard and medium in AFK only"), now conditional:** Hard breaches are fixed automatically in HITL 4a and AFK 3z; Judgment findings are never auto-fixed (HITL: the human decides at the ship halt; AFK: advisory in the PR body). One shared contract:
  - **Go/no-go (E4):** after R and L, replay Spike A's sample and count Hard rows that micro-tdd routes Direct or Visual. Below 0.2 per audited slice: drop the fix round and its AGENTS.md exception, keep R and L. If it goes ahead, merge its exception into the existing CI-fix bullet of §4 (a new bullet does not fit the character budget).
  - **Eligibility:** a Hard breach is fixed only if micro-tdd routes its fix Direct or Visual (no runtime behavior change). Logic, Bug, Risk or unsure demotes it to Judgment. Rules bound by `Check:` or excepted are not input (R); this input filter replaces the earlier static list of "mechanical-lintable" rules.
  - **Who writes:** a fixer subagent follows micro-tdd and edits files only. The 4a lead verifies and commits `fix(BT-n): standards` under a narrow §4 exception modelled on the CI-fix one, so it never edits production code and its context stays isolated. Under 3z the Step 2A implementer is the single code writer and commits; the orchestrator verifies. §4's "subagents never commit" line stays.
  - **Bounds:** one round, all eligible rows batched, at most 2 commits, the CI-fix file cap; it never uses the 3z `attempt` budget and never sets `status:blocked`. A red suite, floor guard or file cap, or a Spec regression, discards or reverts the round and lists the rows advisory; the slice ships.
  - **After the round:** the Standards auditor re-checks the changed lines, the Spec auditor re-audits only rows whose files changed (delta rule). `std_fixed` joins the `audit:` line.
  - **Not chosen:** routing back to 3d (needs a manual `/3d` run and a fresh 4a in HITL, since lifecycle skills cannot invoke each other); plain inline 4a edits (taints the isolation rule).
  - Open for 3d: exact caps, demoted-row labelling, and where the round sits among the 4a phases so `audit-only` keeps its name.
- **Replay (B):** the replayable known blockers (the research doc lists 16; the case list is frozen first and drops cases with no recoverable pre-fix SHA) plus up to 4 clean controls, each checked out at its pre-fix SHA in a temp worktree; one cumulative-unit Spec audit plus a repeat per-slice audit to measure run-to-run variance. Sonnet-class subagents with lean inputs; controls and repeats only if inconclusive. Success criteria are declared before the run.
- **Checkpoint (C):** after the replay and about two weeks of slice-1 data (floor: 15 instrumented slices per repo), decide keep per-slice / per-unit Spec audit. A per-repo override (small config field read by 4a Phase 1, default = the framework rule) is added only if the instrumented data shows a material difference between repos.

## Not doing
Auto-fixing Judgment findings; a framework check runner or detector library; automatic promotion of rules to checks; routing Standards fixes back through a full 3d run in HITL; epic-only audits now; any diff-shape gate (saves <= ~10%); changing the Spec confidence threshold; a shadow PR-level audit on the ship path (adds minutes, sees only residual misses, duplicates the epic audit).

## Done when
