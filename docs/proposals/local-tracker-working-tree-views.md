# Proposal: Local Tracker Working-Tree Views (`.memory/BOARD.md` + `.memory/board.html`)

**Status:** Approved Design -> Ready for Implementation (`v5.4.2`)
**Tracker Mode:** `tracker: local` (`issues.py`)
**Constraints:** No additions to `/0a-start-session` or `/0b-stop-session`; no HTTP server (static HTML opened/refreshed via `file:///` URI).

---

## 1. Problem Statement

Under `tracker: local`, `issues.py` stores issue files on the orphan `<repo>/issues` branch via git plumbing (`commit-tree` + `update-ref`). While this prevents cross-branch divergence, PR diff churn, and merge conflicts, the working tree contains zero visible indication of what issues are `in progress`, `ready` / next, or `blocked`. Existing views (`issues.py summary`, `issues.py board --web`) require manual invocation and leave no persistent glanceable view in the IDE explorer or Obsidian.

---

## 2. Solution Design

Keep `<repo>/issues` as the sole authoritative store, and automatically project two **read-only, gitignored** working-tree views inside `.memory/` on every store mutation:

1. **`.memory/BOARD.md`** — glanceable Markdown dashboard visible directly in IDE explorers and Obsidian (beside `.memory/STATUS.md` and `.memory/resume/`).
2. **`.memory/board.html`** — static, self-contained Kanban HTML board opened once via copy-pasted `file:///` URI (`Path.resolve().as_uri()`) and refreshable with `F5`, preserving the existing drag-and-drop → copy-paste `issues.py apply-moves -` workflow.

### 2.1 Why `.memory/` (and not `.tmp/` or repo root)
- Placing generated files in `.tmp/` without editing `/0b-stop-session` triggers `0b`'s Step 8b `.tmp/` triage prompt at the end of every session.
- Placing them at repo root triggers `4a`'s `[UNCOMMITTED]` clean-tree guard in repos that have not re-run `/stratosphere-update`.
- `.memory/` already houses gitignored folder-state artifacts (`.memory/STATUS.md`, `.memory/resume/`) and is exempt from `4a`'s clean-tree guard. Naming the file `BOARD.md` (not `BACKLOG*`) also avoids retired `BACKLOG_MAP` terminology.

---

## 3. Detailed Specification

### 3.1 `.memory/BOARD.md` Layout
- Banner: `<!-- GENERATED BY issues.py — DO NOT EDIT -->`
- Metadata header: `Branch`, `Ref` (`<branch>@<short-sha>`), `Updated` (UTC ISO timestamp), and clickable/copyable `<file:///.../.memory/board.html>` URI (`Path.resolve().as_uri()`).
- Sections (open work prioritized first):
  1. **In Progress** — `id`, `title`, `claimed_by`, `milestone`, `parent`.
  2. **Ready / Next** — unblocked `planned` slices sorted by `scope:baseline` → `scope:differentiator` → unlabelled → ICE descending → ID (matching `/3c-sprint-planning`), plus `needs_spec` Spikes clearly marked `[SPIKE]`.
  3. **In Review** — issues awaiting merge.
  4. **Blocked** — distinguishes `status: blocked` (on hold) from `status: planned` with unmet `effective_blockers` (listing blocker IDs).
  5. **Open Epics / Milestones** — compact progress counts (`done / total` slices).

### 3.2 `.memory/board.html` & `board.html` Enhancements
- `issues.py` enriches the `board --web` JSON payload while keeping `board.html`'s generic schema intact:
  - Injects `ready` or `blocked` into `cards[i].labels` for `planned` issues so the existing tag-pill bar filters ready vs. blocked work with zero JS changes.
  - Populates `meta` with `milestone`, `ice`, and `claimed_by`.
  - Populates an optional `details` string with `body` and `comments` for **open** issues only (omitting archived `done` issue bodies to prevent HTML bloat; escaped via the existing `<>&\u2028\u2029` sanitizer).
- `src/skills/plan-html/assets/templates/board.html` updates (preserving `test_issues.py` and `verify_plan_html.mjs` `MockElement` invariants):
  - Displays `milestone`, `ice`, and `claimed_by` chips when present in `meta`.
  - Adds an explicit **Details** button on cards (preserving single-click selection for `j/k/h/l/1-9` keyboard moves) that renders `card.details` into a pre-existing drawer container via `innerHTML` only (no `document.createElement`, no `classList.toggle`, and keeping exact `.board-card:not(.filtered-out)` count at 3).
  - Exports `meta` and `details` cleanly in `toMarkdown()`.

### 3.3 Refresh Triggers & Safety Invariants
- **Auto-refresh on mutations:** At the end of `init`, `create`, `set`, `claim`, `close`, `reopen`, `label`, `apply-moves`, `merged --close`, `migrate`, non-resume `comment`, and `sync` (when the ref advances).
- **Pure reads stay side-effect-free:** `get`, `list`, `wip`, `ready`, `check`, `summary`, `branch` never write working-tree views.
- **Explicit command:** `issues.py refresh` unconditionally regenerates `.memory/BOARD.md` and `.memory/board.html` and prints both paths plus the `file:///` URI (`Path.resolve().as_uri()`). `issues.py board --web` also prints the `file:///` URI.
- **Gitignore purity gate:** Auto-refresh writes a target file **only if** `git check-ignore -q <path>` exits `0`. Bare test repos and un-updated projects without `.gitignore` rules stay untouched, and existing mutating-command stdout (`[INIT ...]`, `BT-L-...`, etc.) remains unchanged.
- **Atomic post-CAS writes:** Re-read `head(tracker.ref)` *after* `update_ref` succeeds and write via temp-file + `os.replace()` to avoid Windows concurrency `WinError 32` or out-of-order overwrites.
- **Best-effort HTML on auto-refresh:** Wrap HTML rendering during auto-refresh in `try/except IssuesError` so a missing `board.html` template never aborts a tracker write.

### 3.4 Scaffolding, Memory Lint, and OKF Viewer Integration
- `src/scripts/scaffold.py`: add `.memory/BOARD.md` and `.memory/board.html` to `GITIGNORE_ENTRIES`.
- `src/scripts/validate_memory.py`: exclude `.memory/BOARD.md` from OKF frontmatter/wikilink checks (matching `STATUS.md` and `resume/`) and warn if tracked by git.
- `src/scripts/okf_view.py`: skip `.memory/BOARD.md` in `rebuild_indices` and `items_to_copy` so `0d` never indexes a gitignored file into tracked `.memory/index.md` or `docs/okf-view.html`.
